SECURE SANDBOX

Real text-processing tools,
driven from the browser.

FlintBox runs actual jq, grep, sed, awk and cut binaries inside a hardened container against data you paste or pull over HTTP. No shell. No JavaScript mocks.

Open the app Run it yourself
$docker run -d -p 3000:3000 --read-only --tmpfs /tmp:size=10m --cap-drop ALL --security-opt no-new-privileges ghcr.io/4drian0rtiz/flintbox:latest

Five tools, one screen

Pick a tab, type the flags or expression, hit Run. The command preview bar shows exactly what will execute: $ tool params < stdin.

jq

Filter and transform JSON. Live JSON lint on the input and a one-click Format button.

.[] | .name

grep

Search lines by pattern. Case-insensitivity, inversion, context and counts.

-i root

sed

Stream edits: substitute, delete, print ranges, transliterate.

s/error/WARN/g

awk

Field-oriented programs: columns, sums, conditionals, BEGIN/END blocks.

'{print $1, $3}'

cut

Slice by delimiter, field, character or byte range.

-d, -f1,3

Help drawer

The ? Help button runs tool --help on the real container binary, with a structured cheat-sheet fallback.

Feed it data three ways

text

Paste

Type or paste straight into the input pane. That text becomes the tool's stdin.

http

HTTP fields

Switch the input source to http and fill a small form: method, URL, headers, body. On Run, FlintBox fetches it through the backend proxy and pipes the response body into the tool.

curl

Paste a curl command

The curl sub-mode parses a real command (-X, -H, -d, --json, -L, -s and more) and fills the fields for you.

Running a command

  1. Choose a tool tab (jq, grep, sed, awk, cut).
  2. Enter the flags or expression in the params field. The preview bar assembles the command as you type.
  3. Put data in the input pane: paste it, or set the source to http and give a URL.
  4. Press Run or Ctrl+Enter / ⌘+Enter.
  5. Read stdout in the output pane; the exit code, elapsed time and any stderr show alongside.

The last 10 commands are kept in localStorage and shown as chips under the workspace. Click one to reload that tool and params.

Why it is safe to self-host

  • No shell. Every binary runs via execFile with shell: false at hardcoded absolute paths, never resolved from PATH, never string-interpolated.
  • Whitelisted tools. Anything outside jq/grep/sed/awk/cut is rejected before execution.
  • Bounded input. Input is capped at 100 KB, params at 500 chars, output at 2 MB, each run at a 5 s timeout.
  • SSRF guards. The HTTP proxy blocks private, loopback and link-local ranges, and enforces its own size and timeout limits.
  • Hardened container. Read-only root filesystem, dropped capabilities, no-new-privileges, 0.5 CPU / 128 MB.
  • No auth by design. It is meant to run on a network you control; put it behind your own reverse proxy if you expose it.

Run it yourself

Docker image (recommended)

$docker run -d -p 3000:3000 --read-only --tmpfs /tmp:size=10m --cap-drop ALL --security-opt no-new-privileges ghcr.io/4drian0rtiz/flintbox:latest

From source (Docker Compose)

$git clone https://github.com/4drian0rtiz/flintbox $cd flintbox $docker compose up --build -d

Builds the React frontend in the image; the runtime serves the static bundle.

Local development

$pnpm install # React + Vite toolchain $node server.js # API on :3000 $pnpm dev # Vite UI on :5173, proxies /api
